# WORK-07 — Milestone A: Explicit Task Contracts + Bounded Completion Gate

**Version:** A-DESIGN-001 · **Date:** 2026-11-13 · **Owner:** RIGHTWARE  
**Status:** ENGINEERING SPECIFICATION / CANDIDATE for implementation. This document is NOT evidence that the production functionality exists.  
**Provenance:** prepared by ChatGPT on operator instruction after R3-C2-019; engineering code implementation remains a separate controlled step.  
**Baseline:** `develop` `906e92c9dfebbbf9e5ea8c7ed51854ef3aefc18b` (3/3 CI success observed).

## 1. Problem and target behaviour

The pinned OpenJarvis may end the task when it emits a plausible final answer after visiting information pages, even when the user requested two original documents. The current `AgentReply.completion = ANSWERED_WITH_SOURCES` may indicate that **some** page was successfully retrieved, not that **every mandatory task objective** was satisfied.

**Milestone A goal:** for an **opt-in and narrow** class of public read-only browser tasks, accept a trusted explicit checklist of objectives, monitor actually executed tool outcomes, conservatively verify operational completion, and return a truthful terminal state. This must not change behavior of sessions **without** a trusted contract. The correct result for absent/ambiguous proof is INCOMPLETE or UNKNOWN, never a misleading DONE.

Out of scope: arbitrary Portuguese NLP objective extraction; dynamic user approvals; filesystem modifications; real Windows side effects; durable checkpoint/resume; PostgreSQL or other Shared service; Qwen inference during development; migration of pinned OpenJarvis; general factual truth verification.

## 2. Product-facing contract (design candidate, NOT current API)

Minimal proposed typed record:

```python
@dataclass(frozen=True)
class BrowserObjective:
    id: str                      # unique within trusted contract
    action: Literal["open_original", "read_page"]
    target_url: str              # exact approved HTTPS target, used as expectation
    mandatory: bool = True
    identity_rule: str = "approved_exact_url_and_content"
    expected_content_sha256: str | None = None
    expected_doc_marker: str | None = None

@dataclass(frozen=True)
class TaskContract:
    schema_version: Literal["A1"]
    contract_id: str
    origin: Literal["approved_preset", "operator_confirmed"]
    objectives: tuple[BrowserObjective, ...]
    allow_hosts: tuple[str, ...]
    source_policy: Literal["public_read_only"]
    max_continuations: int = 1
```

**Trust boundary:** a string or JSON produced by the LLM, page text, memory, or an arbitrary process argument is **not automatically** an approved contract. An `approved_preset` must be selected from trusted application code/config; an `operator_confirmed` checklist requires a genuinely authenticated/interactive confirmation mechanism. If that mechanism does not exist, **defer operator_confirmed to later**. A production entrypoint may start with approved presets only.

Validate before starting: non-empty distinct IDs, ≥1 mandatory objective, supported action kinds, HTTPS URLs with hostname in the existing approved allowlist, bounded list length, safe URL normalization, distinct/repeated objective semantics, allowed schema versions; strict reject of unknown fields or invalid/dangerous objectives. A contract is not a new grant. All existing AgentPolicy/browser controls remain decisive.

**Scope safety:** target URL alone cannot prove that a webpage is the authentic original. Without a stronger content proof (trusted digest/marker plus source provenance checks), report `UNKNOWN_IDENTITY` instead of `COMPLETE_VERIFIED`. An untrusted page may contain fake markers; authenticity requires a trusted predeclared rule or publisher-controlled provenance. For generic targets where identity cannot be established, operational proof may only be `PAGE_OBSERVED` (not `ORIGINAL_VERIFIED`).

## 3. Minimal runtime receipts (design candidate, not a schema migration)

For a single in-memory `AgentSession.run()`, introduce structured *internal* event receipts emitted at the **actual execution boundary**, ideally alongside `_PolicyTool.execute`/policy outcome recording, rather than reconstructing joins from matching truncated hashes:

```python
@dataclass(frozen=True)
class ExecutionReceipt:
    run_id: str                  # generated by trusted runtime for one run
    call_id: str                 # exact model proposal id or stable runtime-generated link
    sequence: int                # monotonic per-run
    tool_name: str
    authorized: bool
    executed: bool
    status: str                  # actual ToolOutcome.status
    source_url: str | None
    page_sha256: str | None      # digest and explicit scope, not view hash
    page_hash_scope: Literal["raw_page", "model_view"] | None
    content_type: str | None
    provenance: str             # known runtime emission path, not arbitrary metadata
```

A call that is authorized but never actually executed must produce `NOT_EXECUTED`, not an OK receipt. Missing call ID, duplicate ID, duplicate sequence, missing audit, orphan approval, or ambiguity **must not** be silently linked to an objective. Batching, approval timing and execution timing should remain under existing AgentPolicy gates. Keep evidence redaction: never persist page text, typed text, secrets or raw conversation in receipts. No need for a persistent database in Milestone A.

**Do not retrofit `G2_OBSERVATIONAL` from `labs/work07_r3c2/live_receipt_adapter.py` into an authenticated G2 receipt:** that adapter is a proof of feasibility, not a durable identity guarantee.

## 4. Completion predicate and states

Keep two logically independent dimensions:

- **Operational state**: `COMPLETE_VERIFIED`, `INCOMPLETE`, `UNKNOWN`, `HALTED`, `ERROR`.
- **Factual verification**: `NOT_VERIFIED` unless an explicit verified-answer mechanism exists; tool execution does not imply factual correctness.

Proposed public-facing result additions (opt-in only) may include `objective_results` (objective_id, state, reason, evidence refs) and `completion_gate` (code, evaluated, budget_used, contract_id). Preserve existing no-contract reply shape exactly if possible, or add backward-compatible fields with defaults. Do not silently redefine `ANSWERED_WITH_SOURCES` everywhere: that would break historical behaviour/tests; for contracted tasks, the final state must not claim completion when mandatory objectives remain unsatisfied.

Completion logic:

1. Contract valid and trusted, at least one mandatory objective;
2. For each mandatory objective, match an actual authorized/executed outcome tied to this run, with verified target and identity rule;
3. No forbidden/disallowed operation performed; no unaccounted pending approval; halt/deadline/cancel budget respected;
4. If any missing: `INCOMPLETE` with missing IDs, or `UNKNOWN` if ambiguity prevents assessment;
5. If interrupted: `HALTED` without extra inference; if audit integrity fails: `ERROR`;
6. Only all required objectives fulfilled -> `COMPLETE_VERIFIED` (operational, not factual).

**No `all([])` success.** Repeated objectives requiring two distinct executions must require two distinct receipts; preserving labels alone is not enough. Conditional/ordered objectives must not be allowed into the supported A1 schema until order/conditions can be enforced; unsupported contracts rejected, not ignored.

## 5. Bounded continuation

Use the already-demonstrated `_GuardedEngine` interception boundary, but unlike E1 do NOT allow a continuation when the orchestrator has no remaining turn to execute its requested tools. Never reset tool quotas or AgentPolicy state. Every generated response counts against both orchestrator accounting and the extra continuation budget; enforce a global upper bound independent of the upstream `max_turns`. Check cancel/deadline/max_calls before each generation and each tool call. On last turn or exhausted budget, return `INCOMPLETE`/HALTED truthfully without sending useless feedback.

The corrective feedback must be generated by trusted code using **IDs and safe labels only**; do not inject page body or untrusted instructions into it. If the model proposes a disallowed tool, policy denial stays authoritative; the gate must not retry an irreversible side effect or expand grants.

## 6. Implementation plan (separate PR/checkpoints)

**A0 — contract specification, compatibility and falsification.** Confirm exact APIs and repo internals, agree on supported first preset(s), data shape, compatibility requirements, explicit threat model. Add test-only schemas/fixtures before modifying production. Gate: operator review for scope, since this step is design-only.

**A1 — trusted opt-in entry and validation.** Introduce an approved preset read-only objective contract at the session boundary (or smaller explicit factory) without an agent-exposed ability to elevate objectives. Contract validation and default-off behavior are tested. Any change to `rightware/` requires explicit implementation approval.

**A2 — in-run structured receipts.** Instrument authorization/execution/output correlation in production without modifying the pinned vendor or weakening policy. Reconcile NOT_EXECUTED and exact source identity. Test denial and ambiguous chain.

**A3 — deterministic completion evaluator.** Implement objective check, `UNKNOWN/INCOMPLETE` mapping and code-generated feedback with the bounded recovery established by E1/E4. Ensure `ANSWERED_WITH_SOURCES` does not hide incomplete contracted tasks, but non-contract sessions remain compatible.

**A4 — end-to-end FAKE acceptance.** Re-run synthetic archive tasks A–E and new negative fixtures with the **production implementation in opt-in mode** and compare on objective-level evidence. Report call count, quota, halts, audit, link visibility and user-facing status. No Qwen until these are green.

**A5 — later separate authorization:** real Qwen CPU/GPU acceptance, user experience checks and eventual production rollout. Not approved by this document.

At each checkpoint: verify HEAD/tree/CI, commit appendix in HANDOFF with exact tests and outcomes, and preserve concurrent changes.

## 7. Acceptance test matrix for production-gated milestone

| ID | Case | Expected result |
|---|---|---|
| A-01 | No contract, original regression suite | Existing behaviour remains unchanged |
| A-02 | Trusted 2-original preset, only information pages read | `INCOMPLETE`, missing both original objectives |
| A-03 | Both original docs truly opened and trusted identity checks satisfied | `COMPLETE_VERIFIED` operational only |
| A-04 | One original is HTTP 404, REFUSED or NOT_EXECUTED | `INCOMPLETE`, no false receipt |
| A-05 | HTTP 200 challenge/catalogue with matching title/URL | `UNKNOWN` or `INCOMPLETE`, never PASS |
| A-06 | Missing/foreign/duplicate receipt call ID or run ID | No pass, audit anomaly surfaced |
| A-07 | Two identical required executions; only one receipt | `INCOMPLETE` |
| A-08 | Unsupported contract source/version/conditional/dependency | Reject or UNKNOWN; never relaxed to PASS |
| A-09 | Empty objectives, all optional or duplicate IDs | Reject before execution |
| A-10 | Prompt injection attempts to mark DONE or change objectives | Rejected, unchanged required objectives |
| A-11 | Quota exceeded / cancel / deadline | Halt without extra model or tool calls |
| A-12 | Last orchestrator turn, follow-up would be useless | No wasted retry; truthful incomplete |
| A-13 | Attempt to expand host allowlist, permissions or side effects | Existing policy denies; no new grant |
| A-14 | Result content hash/truncation/version mismatch | Unknown or failed objective, not PASS |
| A-15 | Product completion & reply JSON disagree with objective result | Fail test; no false ANSWERED_WITH_SOURCES terminal for contracted requests |
| A-16 | Trace opt-out or absent observational trace | No fabricated G2; use trusted instrumented receipt only |
| A-17 | Factual correctness not independently checked | `answer_factually_verified=False` |
| A-18 | No real original identity verifier configured | `UNKNOWN_IDENTITY` even after successful page load |

**Nonnegotiable release gate:** zero false COMPLETE on negative fixtures, no policy regression, no data leaks in audit, no unlimited retry, no orphaned approvals, no skipped tests in pinned venv, verified CI on the exact candidate HEAD and no historical Qwen status alteration.

## 8. Risks and decision points

- **Trust bootstrap**: approved preset must be under trusted operator application/config, not arbitrary model text.
- **Semantic identity**: source URL/hash/marker is not itself proof of publisher authenticity. Narrowly define supported document originals.
- **Migration compatibility**: new contract/status fields must not break users with the old AgentReply/JSON.
- **Concurrency**: event identity and sequence must be unambiguous; avoid retroactive matching after the fact.
- **Resource budget**: 4b local model context and last turn limits remain unmeasured in this milestone.
- **Scope creep**: free-form parsing, arbitrary webpages, crash persistence, voice UI and Shared integration are separate milestones.

**Recommended next operator decision:** approve only **A0 specification validation and A1 implementation design**, then authorize A1–A4 code change per explicit scoped work order. Nothing here authorizes switching on the completion gate by default or Qwen.
